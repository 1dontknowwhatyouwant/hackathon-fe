# Hackathon FE

Next.js App Router 기반의 해커톤 Frontend 프로젝트입니다.

## 기술 스택과 선택 이유

| 기술           | 선택 이유                                                                                                                                                                                                 |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Node.js 22     | Next.js 16의 실행 기반을 팀 전체에서 통일하기 위해 사용합니다. `.nvmrc`와 PR CI에 버전을 명시해 로컬과 자동 검증 환경의 차이를 줄였습니다.                                                                |
| Next.js 16     | `src/app`의 App Router를 기반으로 페이지와 레이아웃을 구성하며, 파일 기반 라우팅과 서버·클라이언트 컴포넌트 분리를 활용할 수 있습니다. 빌드와 개발 서버 명령도 Next.js 표준 스크립트로 통일되어 있습니다. |
| React 19       | Next.js 16과 함께 컴포넌트 단위로 UI를 구성하는 기반입니다. 화면을 작은 단위로 분리하고 상태 변화에 따라 선언적으로 렌더링하기 위해 사용합니다.                                                           |
| TypeScript     | `strict` 모드와 `allowJs: false`를 적용해 개발 단계에서 타입 오류와 잘못된 데이터 사용을 발견할 수 있습니다. `@/*` 경로 별칭으로 모듈 import 경로도 일관되게 관리합니다.                                  |
| Tailwind CSS 4 | 별도의 대규모 스타일 파일 없이 유틸리티 클래스 조합으로 빠르게 화면을 구현하기 위해 사용합니다. 현재 전역 CSS와 PostCSS 플러그인 구성이 완료되어 있어 컴포넌트에서 즉시 사용할 수 있습니다.               |
| Axios          | 공용 인스턴스에서 API 기준 URL, JSON 헤더, 타임아웃을 한곳에서 관리할 수 있습니다. 이후 인증 헤더, 응답 변환, 공통 오류 처리를 인터셉터로 확장하기에도 적합합니다.                                        |
| Zustand        | React 클라이언트 컴포넌트에서 여러 화면이 공유하는 상태를 적은 보일러플레이트로 관리하기 위해 사용합니다. 현재 스토어도 상태와 변경 함수를 TypeScript 타입으로 명시하고 있습니다.                         |

## 공통 예외 처리 정책

예외를 개별 화면에서 임의로 처리하지 않도록 아래 기준을 합의한 뒤 기록합니다.

| 예외 분류                                         | 감지 위치 | 사용자 안내 | 로깅 정보 | 재시도·대체 동작 | 상위 전파 기준 | 담당 영역                        |
| ------------------------------------------------- | --------- | ----------- | --------- | ---------------- | -------------- | -------------------------------- |
| `[네트워크 / 인증 / 검증 / 서버 / 클라이언트 등]` | `[작성]`  | `[작성]`    | `[작성]`  | `[작성]`         | `[작성]`       | `[프런트엔드 / 백엔드 / 인프라]` |

공통 원칙 체크리스트:

- [ ] 사용자에게 노출할 메시지와 내부 오류 정보를 분리한다.
- [ ] 토큰, 비밀번호, 개인정보를 로그에 남기지 않는다.
- [ ] 복구 가능한 오류와 즉시 중단해야 하는 오류를 구분한다.
- [ ] 로딩 상태가 오류 이후에도 남지 않도록 종료 처리를 정의한다.
- [ ] 동일한 오류가 중복 알림 또는 중복 로그로 기록되지 않게 한다.
- [ ] 예상하지 못한 오류를 처리할 최종 fallback UI를 정의한다.

## 시작하기

의존성을 설치하고 개발 서버를 실행합니다.

```bash
npm ci
npm run dev
```

브라우저에서 [http://localhost:3000](http://localhost:3000)을 엽니다.

## 환경변수

`.env.example`을 복사해 `.env.local`을 만들고 API 주소를 설정합니다.

```bash
NEXT_PUBLIC_API_BASE_URL=http://localhost:8080
```

## 명령어

```bash
npm run dev        # 개발 서버
npm run build      # 프로덕션 빌드
npm run lint       # ESLint 검사
npm run type-check # TypeScript 검사
```

├─ lib/axios.ts     # Axios 공용 인스턴스
└─ store/           # Zustand 전역 상태
